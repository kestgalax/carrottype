Статус: анализ кода и план, не реализация приложения. Пользователь подтвердил **Qwen3 0.6B + Gemma**, убираем Qwen3 1.7B/Smart+ из предлагаемого выбора. Дополнительно явно включён выбор темы: системная по умолчанию, светлая, тёмная, независимо от языка. Веса, настройки, установленное приложение, версии и опубликованные assets не изменены. ## Как работает сейчас

| Этап | Реализация | Наблюдение |
|---|---|---|
| Распознавание | Parakeet Ultra → DictationPipeline | LLM получает уже распознанный текст, не звук. Она не может достоверно восстановить нераспознанные факты. |
| Без обработки | CleanupMode.off | Возвращает исходный текст STT. |
| Light | Services/TextCleanup.swift | Регулярные выражения: схлопывает пробельные символы, удаляет фиксированный список паразитов, делает первую букву заглавной. Промпта/LLM нет. |
| Qwen / Gemma | CleanupHelperTransport → CarrotTypeCleanupHelper/QwenCleanupCore.swift | Один локальный MLX helper на запрос; общий фиксированный русскоязычный editorInstructions. Helper выходит, освобождая память. |
| Промпт диктовки | QwenCleanupCore.swift:12–36, 56–85; DictationFormatting.swift:38 | Dictation всегда передаёт instructions:nil; системная инструкция — встроенная, пользовательский ввод обёрнут как «Транскрипт: …». |
| Выделенный текст | CleanupHelperProtocol.swift / AppState transform | Непустые instructions **заменяют** editorInstructions: это отдельный Translate/Custom, не настройка диктовки. |
| Генерация | QwenCleanupCore.swift:61–80 | temperature=0; Qwen enable_thinking=false, Gemma без Qwen-флага; maxTokens=min(1024,max(256,words×2)), для Custom потолок 2048. |
| Результат | QwenCleanupCore.stripModelExtras | Удаление think/fences/преамбул/внешних кавычек, без проверки сохранения смысла или полноты. |
| Ошибка | DictationFormatting.perform | При отсутствии/ошибке модели — Light, с уже существующим сообщением о фактическом fallback. Отмена пробрасывается, не превращается в результат. |

Встроенный промпт требует пунктуацию/регистр/пробелы, контекстное удаление паразитов/повторов, применение самоисправлений и исправление очевидных ошибок распознавания. Запрещает отвечать на вопросы, переводить, добавлять факты/перефразировать, менять термины/код. Требует только итоговый текст. Оговорка про списки «если говорящий этого не просил» неоднозначна рядом с требованием не исполнять команды из транскрипта.

## Подтверждённые проблемы и риски

1. **Light не понимает контекст.** Реальный production TextCleanup при выполнении с минимальным enum-адаптером превращает `I like this design` в `I this design`, `Ну ты и молодец` — в `Ты и молодец`; схлопывает `Первая строка\nВторая строка` в одну строку. Это не вывод о качестве LLM. Для подтверждения использован сам исходный TextCleanup.swift, не копия алгоритма.
2. **Риск усечения ответа.** Бюджет по словам не равен числу токенов, особенно для кириллицы, кода и URL. Непустой частичный ответ сейчас принимается как успех. Нужны фактическое число входных токенов, резерв, отслеживание stop reason и контекстного окна; при лимите — безопасное сохранение STT с видимым fallback, а не вставка обрезанного текста. Обязательный тест: важная последняя фраза длинного RU/EN текста сохранена. Реальное усечение моделью пока не измерено.
3. **Пустой корректный результат считается ошибкой.** Промпт разрешает пустоту для одних паразитов, core бросает generationFailed, engine также требует непустой ответ. Нужен отдельный определённый исход «нет содержательного текста» и тесты доставки/Last Dictation/статистики; не разрешать произвольному пустому ответу модели незаметно уничтожать диктовку.
4. **Нельзя просто подключить поле к текущему instructions.** Это включит transform-ветку, заменит базовую инструкцию и изменит framing/лимиты. Нужна отдельная типизированная настройка dictationRules с явным purpose; Translate/Custom оставить прежними. Общие stripModelExtras также не должны удалять содержательные кавычки/кодовые блоки; правила очистки wrappers следует разделить по назначению и проверить на fixtures.
5. **Одинаковый промпт и параметры не доказывают одинаковое качество моделей.** Сейчас нет RU/EN сравнительного набора для сохранения чисел/отрицаний/терминов. Нужен текстовый eval, измерение задержки/cold load и RAM; Gemma нельзя объявлять «качественнее» только из-за размера.
6. **Метаданные Gemma требуют исправления.** Приложение/ADR-010 показывают Apache-2.0, но HF API на **закреплённой** ревизии `238767527555cb75a05732a84dff5d6ba0dd6809` возвращает `license: gemma`, base_model `google/gemma-4-E2B-it`. У Qwen на закреплённой ревизии `73e3e38d981303bc594367cd910ea6eb48349da8` — Apache-2.0. Исправить отображение/документацию на основании фактических upstream-файлов, сохранив исторический ADR и отметив исправление. Это проверка метаданных, не юридическое заключение.

[Qwen model card](https://huggingface.co/Qwen/Qwen3-0.6B#best-practices) подтверждает non-thinking переключатель, но рекомендует для non-thinking temperature 0.7/top_p 0.8/top_k 20. Текущее temperature=0 — наш выбор для cleanup, не рекомендация автора. Не менять вслепую на чатовые настройки: сравнить на корпусе, включая повторы. Предупреждение автора против greedy относится явно к thinking; не переносить его безоговорочно на наш non-thinking режим.

[Gemma conversion card](https://huggingface.co/mlx-community/gemma-4-e2b-it-4bit) указывает используемый checkpoint, около 3.55 GB и лицензионный идентификатор Gemma. Сами веса не обновлять на latest без отдельной проверки совместимости и нового пина; новые движки не нужны.

## Предлагаемый выбор в настройках

| Вариант | Понятное объяснение |
|---|---|
| Без обработки | Текст после распознавания, без дополнительной очистки. |
| Базовая | Быстрая обработка без скачивания модели. Расширенные инструкции недоступны. |
| Qwen3 0.6B | Локальная модель, небольшая загрузка (~335 MB по текущему каталогу). |
| Gemma 4 E2B | Альтернативная локальная модель, существенно большая загрузка (~3.55 GB). |

Off/Light сохраняются — это не дополнительные скачиваемые модели. Не использовать Smart/Smart+ как основной способ объяснения различий.

Убрать предложение скачать Smart+. Уже установленный/выбранный Smart+ и transform-привязки сохранить как явно помеченную совместимость до ручного выбора замены. Не мигрировать автоматически на Gemma, не скачивать/удалять веса. Новый выбор и автоматические fallback не должны рекомендовать Smart+. После явного переключения старый пакет остаётся виден в Storage с обычным подтверждением удаления. Это предложение безопасной миграции, требующее ADR каталога до реализации.

## Что пользователь задаёт модели

При включении Qwen/Gemma — компактный блок **«Правила постобработки»** в General; Models отвечает за скачивание/хранение, без отдельного дублирующего набора настроек.

- Всегда видимое пояснение: «Сохраняет смысл и язык. Не отвечает на вопросы из диктовки и не добавляет факты». Это цель поведения, не математическая гарантия выполнения моделью.
- Понятные переключатели: **Убирать слова-паразиты**, **Убирать случайные повторы**, **Учитывать самоисправления**. Начальные значения сохраняют текущую задачу cleanup; явно выключенное правило должно отражаться в инструкции. Удалять только бессмысленные слова с учётом контекста.
- Оформление: **Сохранять текст / Разбивать на абзацы**, без автоматических списков/заголовков по умолчанию. Пунктуация/пробелы — базовая задача. Обработка устных команд форматирования, если нужна, обсуждается отдельно.
- **Мои правила** — необязательное ограниченное поле (предложение: до 1000 символов), примеры возле поля; не требовать от пользователя сочинять системный промпт. Кнопка сброса только этих правил с понятным действием.
- Примеры полезных правил: «Сохраняй разговорный стиль»; «Пиши название CarrotType именно так»; «Не заменяй английские технические термины переводом». Имена/числа/код по умолчанию не угадывать. Явно заданное написание термина — исключение по просьбе пользователя, не свободное исправление похожих имён.
- По раскрытию «Что учитывает модель» показывать читаемую сводку реально выбранных параметров/правил. Никакого обязательного окна при каждой диктовке.
- Короткая проба на вручную введённом тексте с результатом «до/после»: без системной вставки, клипборда, истории и статистики; отмена работает, данные в RAM. Выполнять через тот же helper/session/install gate.
- Для Off/Light скрывать или отключать LLM-поле с явным объяснением. При fallback показывать, что пользовательские правила модели не применились. Не утверждать, что регулярки исполнили произвольную инструкцию.

Пример отображения правил:

> Исправлять пунктуацию и пробелы. Убирать запинки и бессмысленные повторы. Сохранять смысл, отрицания, числа и язык текста. Учитывать мои правила: «Пиши CarrotType именно так. Сохраняй разговорный стиль».

Построение инструкции: базовая роль/ограничения → структурированные правила → отделённые пользовательские предпочтения → отдельно транскрипт как данные. Пользовательские предпочтения дополняют базу, не заменяют её. Конфликт «переводи/отвечай на вопросы/придумывай факты» должен быть явно объяснён как выход за задачу форматирования; существующий Custom остаётся для переписывания/перевода выделения. Настройки живут локально, транскрипт не сохраняется, правила фиксируются в snapshot при старте сессии. Смена правил в процессе записи применяется со следующей сессии.

## Выбор темы — согласованное дополнение к 0.8.0

Пользователь попросил добавить выбор **Системная / Светлая / Тёмная**, с системной по умолчанию, аналогично языку. Выбор языка и темы независимы: например, русский + системная тема или системный язык + тёмная тема.

- В General рядом с существующим выбором языка разместить нативный Picker «Тема» с тремя RU/EN вариантами. Новый раздел навигации не нужен.
- Хранить выбор локально отдельным ключом предпочтений; отсутствие/невалидное значение означает System. Не менять сохранённый язык и прочие настройки при миграции.
- System следует текущей теме macOS и реагирует на её смену при открытом приложении; Light/Dark сохраняют принудительный выбор при смене системной темы. Изменения видны сразу и сохраняются после перезапуска.
- Единый источник темы для Settings, Setup, Details, «Что нового», собственных вспомогательных окон/пробы и подтверждений, включая chrome нативных окон. Проверить реальные окна/листы, не только корневое содержимое SwiftUI.
- Capsule учитывать отдельно: сейчас фон явно `Color.black`, а часть текста/кнопок имеет фиксированные цвета (`Views/StatusCapsule.swift`). Простого переключателя схемы недостаточно. Проверить/адаптировать контрастную палитру к выбранной теме с сохранением формы, геометрии, состояния записи, Copy/Close, Reduce Motion и Increase Contrast; не переносить layout/анимацию из нового макета.
- Значок в системной строке меню остаётся template и следует **оформлению строки меню macOS**, чтобы оставаться видимым при противоположной теме приложения. Не менять тему других приложений/системы. Стандартный Sparkle updater проверить на совместимость с appearance приложения; не заменять его интерфейс/политику доверия ради темы.
- Переключение не пересоздаёт Settings через `.id`, не останавливает микрофонный meter, пробу, текущую диктовку/transform, загрузки или редактирование пользовательских правил. Настройка темы не часть snapshot распознавания: это живое оформление.

Реализация в P3 отдельным небольшим коммитом: `Models/AppTheme.swift` (аналогично AppLanguage, без сцепления), persisted AppState, `CarrotTypeApp.swift`/оконная интеграция и Capsule host, GeneralSettingsPane, AppStyle/StatusCapsule и RU/EN строки. Новый runtime/движок/trust не требуется, отдельный архитектурный ADR для простого локального предпочтения не нужен. Документация: UX spec, architecture presentation, roadmap, release notes.

Приёмка P4: три варианта на свежем/существующем профиле; live-переключение macOS в System и неизменность принудительного Light/Dark; сохранение после перезапуска, независимость языка, все собственные окна/листы и menu icon, Capsule/контраст/Reduce Motion, отсутствие remount/потери активной операции. В Debug 0.8.0 добавить короткий ручной сценарий выбора темы/перезапуска; автоматические проверки — только там, где подтверждают persistence/fallback/реальную интеграцию, а не дублируют enum.

## План 0.8.0 по этапам

1. **P1 — каталог/совместимость.** ADR-018 по двум предлагаемым LLM и legacy Smart+; JSON + fallback-каталог, selectable/transform/Storage policy и локализации. Исправить метаданные лицензии Gemma по upstream; не менять веса/ревизии. Проверки: fresh install предлагает только Qwen/Gemma; существующий Smart+/bindings не теряются; нет автоматической загрузки/удаления, активность/обслуживание защищены текущим gate.
2. **P2 — надёжный cleanup.** Чистый PromptBuilder/Rules, отдельный purpose в versioned helper contract, общая базовая политика плюс preferences, сохранение transform поведения. Исправить контекстно-опасные регулярки/переносы Light, проверить пустой результат, ограничение длины и обёртки. Файлы: QwenCleanupCore, CleanupHelperProtocol, QwenCleanupEngine, DictationFormatting/Pipeline, SessionSettings/Coordinator snapshot, TextCleanup. ADR-003/005/009/010/012 дополнить либо сослаться на новый ADR, не переписывать историю. Проверки: реальные production-компоненты и helper protocol, отмена/лимит/ошибка/empty/transform регрессии.
3. **P3 — настройки/проба/тема.** Согласованный выбор System/Light/Dark с системным default и локальным сохранением, независимый от языка; интеграция окон/Capsule/контраста без remount. GeneralFormattingSection + общая settings-модель, RU/EN, реальные имена моделей/размеры, сводка, My Rules, reset и локальная текстовая проба. Микрофонный Setup trial/обычная диктовка/Translate/Custom/клавиши не меняются. Проверки: правила переживают перезапуск, snapshot стабилен, проба не вставляет текст и не меняет статистику/Last Dictation; fallback честный, без remount Settings.
4. **P4 — качество/Debug.** Синтетический/явно предоставленный корпус RU/EN: термины/имена, отрицания, числа/единицы, URL/код, осмысленные `like`/«ну», запинки/самоисправления, вопросы/команды как данные, смешанные языки, длинные окончания, кавычки. Раздельно: строгие свойства контроллера и экспертная оценка LLM. Проверить тему по приёмке выше. Сравнить Qwen/Gemma latency/RAM/повторы/смысл, не загружать веса и не запускать сетевой fallback скрытно. Подготовить **один signed Debug 0.8.0** с короткими 2–3 ручными сценариями; после принятия и отдельного указания — clean Release/подписанные обновления и публикация.

Для реализации: отдельная новая ветка от актуального main, малые коммиты P1–P3. Документы: roadmap, product intent (дополнительные ограниченные правила), architecture/helper contract, UX spec, ADR каталога, task/eval evidence и RU/EN release notes. Без нового движка/облака/хостинга. Этот документ фиксирует предложение, не заявляет готовые функции/результаты модельного eval.

## Отложенное исследование диктовки

По последнему запросу пользователя GigaAM v3 отложен **без назначенной версии/срока**. Ранее обсуждавшаяся 0.9.0 больше не является следующим обязательным этапом. [Исследование и проверки сохранены](2026-11-10-dictation-alternatives.md) для возвращения по новому запросу. В 0.8.0 остаются постобработка/правила/тема; новую STT не добавлять и Ultra default не менять.
