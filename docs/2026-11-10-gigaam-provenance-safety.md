# GigaAM v3 MLX: происхождение и предварительная проверка безопасности

2026-11-10. Дополнение к [архитектурной проверке](2026-11-10-gigaam-architecture-fit.md) по прямому вопросу пользователя о сторонних весах/рисках. Scope: metadata + просмотр выбранного SDK + синтетический тест путей; **не полный аудит, не загрузка/проверка весов и не гарантия безопасности**. Приложение, реальные файлы/модели/настройки пользователя не изменены.

## Кто что публикует

- Оригинальная модель: [salute-developers/GigaAM](https://github.com/salute-developers/GigaAM), официальный checkpoint [ai-sage/GigaAM-v3](https://huggingface.co/ai-sage/GigaAM-v3).
- Сторонние [Swift/MLX SDK](https://github.com/kruatech/gigaam-v3-mlx) и [конвертированный пакет](https://huggingface.co/kruatech/gigaam-v3-mlx) — Kruatech. Это не официальная Apple-версия и не публикация исходной команды GigaAM. Автор model card заявляет конвертацию e2e_rnnt без дополнительного обучения/finetuning и сравнение с Python reference; нами воспроизведение не выполнено.
- Проверенный SDK commit `95bd42a4b9a65450a24e1898c7d84b85e0e88509`. HF model snapshot на момент проверки `2478743c1c449a468ee163bc3030170d1a2e81fb`.
- В стороннем `manifest.json`: source_model `ai-sage/GigaAM-v3`, source_revision **`e2e_rnnt`** (имя ревизии, не неизменяемый commit). HF API сейчас разрешает это имя официального checkpoint в **`7655ad717f8122257385bb4b2f373db3697e8680`**. Это не доказывает, что автор конвертировал именно этот commit в прошлом: нужно связать источник с конвертацией.
- В SDK snapshot не найден скрипт с именем convert/reference/golden; тестовый каталог содержит BuildWordsTests. Это ограниченный поиск/инвентаризация, а не доказательство отсутствия авторских проверок вне репозитория. Утверждение автора о численной эквивалентности не равно доступной нам воспроизводимой цепочке.

## Что находится в модели

HF API file list: `weights.fp16.safetensors` (445,105,914 B), manifest/README/checksums, tokenizer.model/tokenizer_vocab.json, два frontend массива Float32. Массив весов не загружался. Опубликованный SHA-256 для weights: `2ff6d955a61003e0d3cb2155be36c14aa3df69c879713f30880ddd07d71fde21`, совпадает с LFS metadata того же publisher. Сверка фактически скачанных 445 MB **не выполнялась**.

[Safetensors](https://huggingface.co/docs/safetensors/index) — формат данных тензоров, который избегает механизма выполнения pickle. Но это не сертификат происхождения/качества: SDK использует собственные Swift SafetensorsIndex/SafetensorsMLXLoader, их проверки не наследуют автоматически гарантии reference-библиотеки. Ошибки parser/runtime и намеренно изменённые тензоры остаются отдельными классами риска. В рамках фиксированного recognizer веса сами по себе не имеют сетевых инструментов; исполняемый код библиотеки/загрузчика и его зависимости проверяются отдельно.

У оригинального e2e_rnnt snapshot есть `pytorch_model.bin` и `modeling_gigaam.py`. Формат первого источника тоже не означает безопасное исполнение произвольного remote code: возможную собственную конвертацию проводить в ограниченном окружении, с фиксированными исходниками/хешами и безопасной загрузкой только весов, без слепого trust_remote_code или небезопасной pickle-загрузки.

## Что проверено / найдено

1. В 29 исходниках **библиотечного** target GigaAMKit просмотрены вхождения URLSession/URLRequest/NWConnection/WebSocket/Process/dlopen/HTTP URLs и операции чтения файлов. Прямых сетевых/запускающих shell вызовов по этим шаблонам не найдено. MLX `eval(array)` — вычисление тензоров, не строковое eval кода. Это не динамический сетевой аудит, не проверка всех transitive dependencies/CLI/tests/build environment и не доказательство отсутствия обходного сетевого кода.
2. **Воспроизводимый SDK finding:** ModelBundle добавляет `manifest.weightsFile`/tokenizerFile к modelDirectory без confinement. Синтетический fixture `weights_file: ../outside.bin` принят как существующий файл вне model directory. Проверка выполнена на реальных Foundation-only SDK source (ModelBundle/GigaAMManifest/GigaAMConfiguration/GigaAMError), только на собственных временных dummy files; лог показывает `Synthetic manifest parent traversal accepted: true`. Скрипт `/tmp/carrottype-gigaam-pathcheck.py`. Это отсутствие защиты на SDK-границе, не доказанный exploit в CarrotType: SDK ещё не интегрирован, посторонние данные не читались. До включения нужны allowlist имён, canonical/symlink path checks и проверка всех frontend/tokenizer assets.
3. SafetensorsIndex имеет cap header <128 MiB и некоторые проверки, но parser/loader требуют дополнительной проверки отрицательных/слишком больших offsets/dimensions, checked arithmetic, ожидаемых имён/форм/числа тензоров и размеров относительно файла до allocation/MLXArray. По этому пункту выполнен code review, malformed-weight crash/fuzz tests не запускались; RCE не установлено.
4. Ранее выполненный typecheck всех 29 SDK файлов подтверждает совместимость API, **не безопасность** или совпадение тензоров.
5. Helper process полезен для kill/reap/освобождения RAM, но текущий CarrotType helper **не sandboxed**. Отдельный процесс сам по себе не запрещает сеть/чтение файлов и не является полноценной границей безопасности. Не утверждать обратное в планах/интерфейсе. При необходимости ограничения полномочий helper нужны отдельное решение/ADR и реальная проверка; копировать транскрипты/аудио во внешние сервисы не нужно.

## Как использовать в этапе 0.9.0

**Предпочтительный путь доверия:** восстановить воспроизводимую конвертацию из закреплённого официального checkpoint — самостоятельно либо на основе доступного проверенного скрипта автора. Проверить mapping/допустимые преобразования тензоров, frontend/tokenizer и численную/текстовую эквивалентность на fixtures. Побитное совпадение разных форматов не ожидается; нужен понятный отчёт преобразования. Собственная конвертация уменьшает доверие к стороннему бинарному набору, но не отменяет аудит Swift runtime.

До решения о release:

- Закрепить commit SDK и модели, официальный исходный commit и отдельные **наши** проверенные SHA-256 всех требуемых файлов. Хеш от того же publisher показывает целостность относительно выбранной публикации, не подтверждает, что веса равны оригиналу и не содержат закладки.
- Скачать только фиксированный allowlist assets; не загружать/запускать код из model repo. Проверять пути/ссылки/размеры/схемы до загрузки в recognizer. Закрыть path finding и bounds/alloc checks; негативные fixtures/fuzzing для parser.
- Изолированный build/inference с публичным/синтетическим аудио, без реальных пользовательских моделей/настроек. Проверить файловые/сетевые обращения; после установки recognizer работает offline, никакого скрытого upload/telemetry. Прогнать dependency/supply-chain review.
- Отдельно качество/longform/cancel/RAM/live draft из S1/S2. Хороший WER не доказывает безопасность; чистый сетевой тест не доказывает точность модели.
- До выполнения не маркировать библиотеку «проверенно безопасной» и не выдавать typecheck за security acceptance. Конкретный engine, trust/pinning/download policy описать в ADR; обычные Debug/manual/explicit publication gates сохраняются.

Вывод: сторонняя конвертация сама по себе не доказывает подвох. На данный момент это кандидат для ограниченного исследования с непроверенной цепочкой происхождения и конкретными местами для усиления SDK. Оснований гарантировать production-безопасность текущей проверки нет; подключать без дальнейшей верификации не рекомендуется.
