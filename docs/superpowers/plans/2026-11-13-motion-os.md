# Motion OS Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dogfood and extract a private **Motion OS** kit (Remotion core + optional capture adapters + required `motion run` CLI) with CarrotType as the first consumer, without making Orca a runtime dependency.

**Architecture:** Keep producing films inside CarrotType `artifacts/motion-pilot/` until two **new** template families Pass; draft the skin/core/adapter inventory; then create a separate `motion-os` repo and thin CarrotType `motion/` consumer. Core never imports product UI; skins export scenes/tokens against template contracts; capture adapters are opt-in.

**Tech Stack:** Remotion 4.x + React + TypeScript, Node ≥ 20, FFmpeg 8.x, optional macOS AX/`screencapture` adapters, CLI (Node), AIDOS-style `.ai/` + docs in `motion-os`. Orchestration (Orca/Cursor) optional.

## Global Constraints

- Spec of record: `docs/superpowers/specs/2026-11-13-motion-os-design.md`
- Pilot evidence: `artifacts/motion-pilot/2026-11-13-{island-livedraft-v3,typing-speed,theme}/`
- **No** `macos/` (or other product tree) edits for demo convenience
- **No** git commit/push unless a human maintainer explicitly asks
- Silent master by default; **no mouse cursor** as click language (ring/press/iris only)
- Remotion-only must remain a valid Pass path; capture is optional
- Extract **only after** Task 4–5 gates (two new-family Pass films + inventory)
- Never recommend Naomi models for OpenCode workers
- Do not publish Motion OS publicly until 2–3 products have dogfooded (post-MVP)
