# План улучшений CarrotType: надёжность, Ultra и обновления

Дата: 2026-11-09. База: `main`, `4493f30`, опубликованная версия `0.3.9`.

Статус: этапы 1 (0.3.10, R1–R4) и 2 (0.4.0, M1–M3) завершены и опубликованы после собственных Debug-сборок, ручных подтверждений пользователя и проверки Release DMG. [Проверка 0.4.0](../../debug-review-v0.4.0.md). Этапы 3–5 не начаты. Номера ниже — целевые, до начала каждого этапа сверять с последним опубликованным релизом.

## Основания и границы

- [Product intent](../../product-intent.md): надёжность hotkey → local STT → caret paste важнее широты функций.
- **Сохранение существующих функций:** этот приоритет не разрешает удалять, скрывать или ухудшать существующие полезные возможности ради упрощения кода или интерфейса. Такие изменения сначала отдельно согласуются с пользователем с конкретным описанием того, что исчезнет или изменится. Уже согласованное сокращение STT до Parakeet Ultra ограничено моделями диктовки и не распространяется на остальные функции.
- [Roadmap](../../roadmap.md): последовательность этапов ниже заменяет прежний приоритет исследовательских spikes.
- [Architecture](../../architecture.md), [Setup UX](../../specs/ux-setup-status.md), [Constraints](../../../.ai/constraints.md).
- Решение пользователя: предлагать только **Parakeet Ultra для диктовки**; добавить обновление приложения из GitHub Releases.
- Qwen/Gemma пока сохраняются для форматирования и преобразования выделения. Сокращение этих моделей требует отдельного продуктового решения.
- Аудио и тексты остаются локальными. Обновления получают только метаданные релиза и бинарные архивы; не отправляют пользовательский контент.
- Нотаризация остаётся отдельным необязательным улучшением, а не условием начала интеграции updater.

Предварительный аудит выявил проблемы по коду; живой UI не проверен из-за отсутствия Accessibility у Orca Computer Use. Риск блокировки pipe helper не воспроизведён. Перед исправлением конкурентных сценариев нужны воспроизводимые проверки.

## Последовательность версий

| Этап | Версия | Результат | Зависимость |
|---|---|---|---|
| 1 | `0.3.10` | Результат можно восстановить, буфер защищён, ошибки видны | Текущая `main` |
| 2 | `0.4.0` | Ultra — единственная предлагаемая STT; безопасная миграция | Этап 1 интегрирован |
| 3 | `0.5.0` | Проверка, скачивание и установка обновлений внутри приложения | Этап 2 интегрирован; ADR updater принят |
| 4 | `0.6.0` | Понятный первый запуск и компактные настройки | Этапы 2–3 интегрированы |
| 5 | `0.6.1` | Управление сессией отделено от AppState, проверки используют production-код | Этапы 1–4 интегрированы |

Каждый этап — отдельная ветка от актуальной default branch после интеграции предыдущего. Внутри этапа задачи выполняются небольшими последовательными изменениями. Подготовка к релизу и сам выпуск — разные действия: merge, tag, публикация требуют отдельного указания пользователя. Настоящий план не разрешает автоматически публиковать все будущие версии.

Обязательный gate для каждой версии (указание пользователя 2026-11-09): сначала собрать и проверить Debug build, передать его пользователю с чеклистом ручной проверки и дождаться явного подтверждения перед публикацией. После исправлений по проверке передавать обновлённую Debug-сборку. До подтверждения не публиковать версию и не переходить к следующему релизному этапу.

## Этап 1 — 0.3.10: сохранность результата и диагностика

Ветка: `fix/dictation-reliability`. ADR: существующие ADR-009, ADR-013, ADR-015; уточнить UX и срок хранения последнего результата в спецификации. Историю текстов на диске не добавлять.

### R1. Защитить clipboard transaction

- Файлы: `TextInsertionService.swift`, `SelectionTextService.swift`, проверки clipboard.
- Восстанавливать снимок только если буфер всё ещё принадлежит данной операции (`changeCount` после собственной записи / копирования).
- Обрабатывать пустой исходный буфер; сохранять все доступные типы и элементы. В selection fallback гарантировать завершение/восстановление также при отмене.
- Готово: новая пользовательская копия не затирается; пустой буфер восстанавливается; несколько элементов и rich text проходят round trip; отсутствие выделения не возвращает старый текст.
- Проверка: изолированный named pasteboard, гонка с внешней записью, отмена и отсутствие selection; ручной copy/paste smoke в редакторе и браузере.
- Документы: Setup UX, roadmap; уточнение clipboard-поведения ADR-015 при необходимости.

### R2. Последний результат и честная обратная связь

- Файлы: `AppState.swift`, `TextInsertionService.swift`, `StatusCapsule.swift`, `MenuBarViews.swift`, `Localizable.xcstrings`.
- Хранить только последний завершённый текст в памяти до замены новой завершённой диктовкой, явной очистки или выхода. Новая запись и её отмена сами по себе не уничтожают предыдущий результат.
- Предоставить «Скопировать последний результат» в меню; при известной ошибке вставки предложить Copy в Capsule. Не менять обычный быстрый hotkey → paste сценарий.
- Различать отправку команды вставки и подтверждённый результат: CGEvent сам по себе не подтверждает изменение текста в приложении. Не обещать универсальную проверку через AX.
- До реализации зафиксировать формулировки статуса и семантику счётчика: без подтверждения вставки показывать завершённые диктовки, не выдавая их за проверенные вставки. Уточнить ADR-013 и подписи статистики; старые агрегаты не удалять и не представлять как ретроспективно проверенные.
- Готово: при ошибке Accessibility готовый текст доступен для Copy; при проигнорированном ⌘V доступно ручное восстановление; текст не пишется в файлы/логи; исходное аудио удаляется по существующей политике.
- Проверка: обычная вставка, поле только для чтения, смена фокуса, отозванное разрешение, отмена следующей записи, выключенная статистика.
- Документы: product intent (последний результат), Setup UX, ADR-013, roadmap.

### R3. Сделать ошибки и обновления доступными при Ready

- Файлы: `CarrotTypeSettingsView.swift`, `SettingsStatusHeader.swift`, `StatusDetailsPane.swift`, `AppState.swift`, `MenuBarViews.swift`, локализация.
- Ссылка на подробности доступна всегда; Ready описывает готовность, а последняя ошибка сессии отображается отдельно.
- Краткое сообщение об ошибке даёт подходящее действие: Copy, открыть разрешения, повторить скачивание. Не сбрасывать ошибку одним пересчётом readiness.
- Готово: Ready + последняя ошибка не скрывают диагностику; существующая ссылка Releases доступна до появления updater; успешная новая операция корректно убирает устаревшее сообщение.
- Проверка: отказ transform, ошибка вставки, ошибка загрузки модели, RU/EN, повторная успешная сессия.
- Документы: Setup UX, roadmap.

### R4. Укрепить IPC helper

- Файлы: `QwenCleanupEngine.swift`, transport-проверки с тестовым helper.
- Читать stdout/stderr во время исполнения; ограничивать объём накопленных данных. Обработать timeout, отмену, ошибку старта и завершение процесса без осиротевших helper.
- Готово: объём вывода больше pipe buffer не блокирует процесс; malformed JSON и ненулевой exit дают контролируемую ошибку; диктовка использует Light fallback, transform сообщает ошибку.
- Проверка: fake helper с большим stdout/stderr, зависанием и некорректным ответом; smoke реального Smart.
- Документы: verification evidence и roadmap; ADR-009 сохраняется, transport и process-per-session не меняются.

Общий выход этапа: Debug build, проверки R1–R4, ручной hotkey → paste и Escape smoke. Новый test target/небольшой harness добавляется здесь только для затронутых ошибок; общий рефакторинг остаётся этапу 5.

## Этап 5 — 0.6.1: поддерживаемость без изменения UX

Ветка: `refactor/dictation-session-lifecycle`.

### C1. Отделить lifecycle сессии от AppState

- Файлы: `AppState.swift`, новый session coordinator/state, `DictationPipeline.swift`, audio/mute/capsule boundaries.
